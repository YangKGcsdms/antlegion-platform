# Agent 生态开发学习路径

> 制定于 2026-08-24。基于 AntLegion 项目现状与个人真实起点的长期规划。
> 原则:**每学一样东西,就在自己的项目里亲手重做对应的那一块;AI 当老师,不当手。**

---

## 一、现状评估

### 已有的(真实资产)

| 资产 | 说明 |
|---|---|
| 设计与协议品味 | AntLegion 的公理(facts-not-commands)、取舍(总序 vs CRDT、recv vs ts)、定位纪律(拒绝成为工作流引擎)是自己做的决定,且经得起推敲 |
| AI 驱动开发能力 | 能把含糊直觉磨成协议规范,并驱动 AI 落地为已发布的 npm 包(@antlegion/bus、ant、dsh、alias 四包) |
| 工程纪律的形 | conformance vectors + Python 跨语言校验、CI vectors-guard、PROTOCOL.md 规范、双语文档 |
| dsh 生态切入点 | 已为 DeepSeek Harness 写了官方插件(@antlegion/dsh),是进入目标团队视野的现成通道 |
| 论点储备 | "长期协作坍缩成共享日志"(物理动作不可幂等 ⇒ 总序值得付出)、"因果链是承重的而非描述性的" |

### 缺的(诚实清单)

- **手上功夫**:真实水平 ≈ 一些 Java + curl 推理接口。代码是 Claude 写的,离开 AI 目前扛不动实现层
- **分布式系统基础**:项目每个决定都踩在这个学科上,但没有系统学过
- **闭卷防守能力**:五个核心机制(见附录自测)还不能脱稿讲清
- **外部性**:零第三方用户、零第二实现、npm 下载量为爬虫底噪水平
- **协议缺口**:大 payload/blob 约定、断连复制、author 级非对称签名(跨组织信任的硬前提)

### 职业目标与双腿走法

长期从事 agent 生态基建(harness / 协议 / 运行时方向,对标 DeepSeek Harness 类团队)。

- **近腿(~6 个月可达)**:开发者生态 / DevRel / 解决方案工程 —— 用 dsh 插件 + 双语文档 + 设计长文当作品集,先进圈子
- **远腿(1–2 年)**:核心基建工程师 —— 靠下面的筑基梯子,进圈后横移

## 二、学习大纲(按优先级与顺序)

### 阶段一:读懂自己的仓库(第 1–2 个月)

教材就是 `antlegion-bus/src/`——概念上完全理解、但没亲手写过的代码库,自带判卷器(`npx vitest run`)。

- [ ] 逐文件精读:`canonical.ts` → `hash.ts` → `log.ts` → `bus.ts` → `fold.ts` → `client.ts` → `server.ts`
- [ ] 每读完一个文件,**合上它**,用自己的话写一页笔记:这个文件对协议负什么责任
- [ ] 读不懂的行让 AI 逐行讲,但笔记必须自己写
- 备注:TS 对会 Java 的人是表亲,不是新语言

### 阶段二:闭卷重写小件(第 2–4 个月)

每天一小时。不开原文件、不用 AI 补全,手写后跑现有测试判卷。头两周的难受就是筑基本身。

- [ ] `globMatch`(canonical.ts,几十行纯逻辑,热身)
- [ ] `stableJsonStringify`(逼自己搞懂浮点渲染与字典序——协议的地基)
- [ ] `fold.ts` 的 `current` / `supersededBy`(协议语义核心)
- [ ] `claimWinner`(写完它,"lowest-seq 为什么无竞态"就不再是背出来的)
- [ ] 顺手把 Python 补到能写基础设施的程度(为阶段三铺路)

### 阶段三:分布式系统正课(第 4 个月起)

- [ ] **《Designing Data-Intensive Applications》(DDIA)** 整本 —— 本领域唯一圣经,AOF/compaction/全序/事件溯源全覆盖
- [ ] 三篇论文:
  - [ ] Kreps《The Log》—— 整个项目的思想源头
  - [ ] Lamport《Time, Clocks, and the Ordering of Events》—— recv vs ts 决策的理论根
  - [ ] Raft 论文 —— 复制故事的入口
- [ ] **里程碑练习:闭卷、不用 AI,用 Python 对着自己的 conformance vectors 手写第二个 fold 实现**
  (一箭三雕:补实现肌肉 + 验证协议可独立实现 + 直接产出"第二实现"里程碑)
- [ ] 余力:MIT 6.824 labs(Go 手写 Raft)

### 阶段四:Harness 内部机制(与阶段三可交错)

没有教材,学习方式就是读源码。

- [ ] 精读 **dsh 源码**并消化(已写过插件,这是面试主场)
- [ ] 对照读 1–2 个开源 harness(codex CLI / Gemini CLI / Claude Agent SDK 示例)
- [ ] 输出:harness 在工具协议、权限模型、上下文压缩上的**取舍对比文章**(此类文章稀缺,自带流量)
- [ ] 向 dsh 本体提高质量 issue(带最小复现)与 PR —— 目标团队 merge 一个实质 PR 胜过 1000 star

### 阶段五:选一根专业化的刺(进圈后)

按稀缺度排,选一个做纵深:

1. **Agent 安全与沙箱**(最稀缺):进程隔离、seccomp/容器、权限模型、prompt injection 防御——env 白名单已摸到门
2. **协议与信任**(最顺的延伸):签名、身份、跨组织互操作——ed25519 proposal 是第一份作业,**自己写**
3. **评测与可观测性**:eval harness、SWE-bench 类基准、OTel GenAI tracing

## 三、LLM 推理侧知识(薄薄一层,散在晚上看)

**判断标准:这个知识会不会改变某个工程决定?会,学;不会,跳过。**

需要(概念级即可,每条都直接改变 harness 工程决策):

- [ ] Tokenization —— 为什么模型数不清字符;影响工具输出格式设计
- [ ] KV cache 与 prompt caching —— 为什么只追加不修改便宜;影响上下文管理与账单
- [ ] 注意力与上下文窗口(每个 token 看得到之前所有 token,代价随长度涨)—— 影响 compaction、子 agent 拆分
- [ ] 采样(temperature/top-p 在分布上做什么;T=0 也不保证确定)—— 连着协议里的 `nonce` 与幂等
- [ ] Embedding 与余弦相似度 —— 检索/记忆系统地基
- [ ] 结构化输出与 tool calling 机制(约束解码)—— evidence shapes 类接口的设计依据

材料(合计十几个小时,看完即够):

- [ ] 3Blue1Brown 神经网络 + Transformer 可视化系列
- [ ] Karpathy《Intro to Large Language Models》讲座
- (Karpathy "Let's build GPT" 留给两年后的好奇心,不进必修)

## 四、数学(两块,都不是"数学课")

- [ ] **概率直觉**(初中程度):分布、采样、期望
- [ ] **评测统计**:方差、样本量、为什么单次运行会骗人、pass@k —— 不懂它做 eval 就是读茶叶

**明确不需要**:线性代数、微积分、优化理论、反向传播、训练动力学、CUDA。
训练模型和使用模型是两个职业;"先学好数学和深度学习再入行"是转行者最常见的自杀路径。
目标画像:懂发动机特性的赛车工程师,不是冶金学家。

## 附录:闭卷自测清单(面试防守线)

不开仓库、不用 AI,能对着白板讲清才算过:

1. lowest-seq claim 为什么无竞态?每个读者为什么算出同一个赢家?
2. 因果环为什么不可构造?(内容寻址的结构保证)
3. claim 过期为什么锚 `recv` 不锚 `ts`?崩溃恢复重派为什么不会撤销真实 resolve?
4. HMAC 换 ed25519 换掉的是什么信任假设?现在的 `sig` 到底证明了什么、证明不了什么?
5. bus 重启从空 journal 恢复时,DCU 的 cursor/fold 如何自愈?(runtime.ts 的 head < cursor 逻辑)

**钉死顺序**:阶段一 → 二 → 三,别倒过来,也别并行铺开。
现在最不缺的是广度,最缺的是"离开 AI 也扛得住"的那一层深度。
第一步本周就能迈:打开 `canonical.ts`,从第一行开始读。
